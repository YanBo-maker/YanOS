# 0005 笔记元数据的 MCP 只读工具：新增 gated 工具，而非并入现有工具

- **状态**：闫博 2026-10-30 裁定
- **日期**：2026-10-30
- **关联**：[0033](../specs/0033-block-mcp-navigation.md)、[0035](../specs/0035-agent-writable-knowledge.md)、[0041](../specs/0041-note-meta-mcp-tool.md)、[0027](../specs/0027-note-metadata.md)、[0001 路线](0001-roadmap-A-D-B.md)、[0002 写入并发](0002-B-write-concurrency.md)
- **源码依据**：main `69510c7`（只读）

## 问题

[0027](../specs/0027-note-metadata.md) 已实现元数据观察（Guest 终端 `meta show`，0027:45–83），但 [0033](../specs/0033-block-mcp-navigation.md) 的六个只读工具只覆盖块导航，MCP 侧没有任何 meta 能力。Agent 读不全一篇带头笔记的头，因此在整文件覆盖时无法无损保留 title/tag。

本机探针实测：只靠 `yanos_block_list` 加 `yanos_block_read` 重建一个 134 字节的带头文件，只能得到 83 字节，差异恰为 51 字节的头前缀；无头文件则完全一致。这确认缺口在读取面而非写路径。

## 三个候选

1. **始终可见的第 7 个只读工具** —— 违反 0035-R1-AC1 与 R12-AC1（默认启动态 `tools/list` 必须与 0033 六工具逐字节相同），否决。
2. **并入 0035 的写开关 `--allow-write`** —— 读能力被写开关门控，语义荒谬，否决。
3. **新增独立只读工具 + 独立开关 `--allow-meta`** —— 默认态不变，与写开关正交，采用。

## 不并入 0035 现有 R 的理由

0035 的三条验收条件共同把工具面钉死为「6 或 8」：

- `0035-R1-AC1`：不带 `--allow-write` 启动时，`tools/list` 与 0033 的**六工具列表**逐字节相同。
- `0035-R2-AC1`：带 `--allow-write` 启动时，依次为**原六个加两个新工具**。
- `0035-R12-AC1`：不带 `--allow-write` 跑 0033 原有检查，**期望输出不改**。

其中 `R2-AC1` 是数量断言，且「带 `--allow-write` 启动」没有排除其它开关，因此两开关同开的十工具态（当时评估为九工具态；后由 0041-R2 增加第二个 meta 工具变为十）在 0035 现有 AC 下无处容身。这类冲突无法用措辞澄清化解——它不是歧义，是计数。要并入就得改已批准的验收条件。

新开 [0041](../specs/0041-note-meta-mcp-tool.md) 可以完全不碰 0035 的 Approved 正文，只加一行前向指针。这符合本仓库既有范式：0035 扩展 0033 时，0033 至今没有任何指向 0035 的指针（`grep -c 0035 docs/specs/0033-*.md` = 0）；0031 的前向指针也是事后由独立文档提交补的，不是扩展动作的一部分。0036 扩展 0021、0032 被 0040 部分澄清，都走同一条路。

## 版本号：保持 0035，不推进为 0041

`serverInfo.version` 保持 `"0035"`。依据是取值规定，不是断言豁免：

- 0035 有四处把该值规定为 `"0035"`（`grep -c serverInfo.version` = 4）：「0035-R1」正文、「0035-R2」正文、「实施澄清（develop-gpt…）」节、以及 0035-R12-AC1。
- 0041 不改写 0035 任何正文，因此必须遵守它的取值规定。

这与 0033 当年推进为 `0033` 不矛盾：0031 全文没有该值的取值规定（`grep -c serverInfo.version docs/specs/0031-*.md` = 0），0033 是**首次**给这个号定值，不是违反既存规定。0033 与 0041 的体例其实相同——都是独立新 spec、都不回改被扩展方：「同一份 spec 内改写」这个区别并不存在（0033 首个提交 `8c1cdf3` 只改了 `docs/STATUS.md` 与 `docs/specs/0033-block-mcp-navigation.md`，未触碰 0031）。

另外「实施澄清（develop-gpt…）」节那条的措辞是「不论是否带 `--allow-write`」，未覆盖 `--allow-meta`；保持 `"0035"` 因此不需要对该条做任何澄清。

## 后果

- 默认态、仅写开关态的两组既有断言（工具列表哈希、工具名称列表、官方 SDK 发现）**一处不改**。
- `serverInfo.version` 不变，故 `README.md`、`docs/mcp-write-tools.md` 里关于版本号与六工具数量的描述也不需要改。
- 需新增 7 工具态与 9 工具态各一条 `tools/list` 断言，以及 `--allow-meta` 重复开关的启动 USAGE 用例。（2026-10-30 更新：0041-R2 加入第二个 meta 工具后，这两种形态现为 **8 与 10**；断言已随 PR #112／#113 落地。）
- `0041-R1-AC9` 把 STALE 固定在 NOT_FOUND 之前，且比较对象是**前身份 `before`**：同一 server 里两族只读工具的错误优先级必须一致，否则调用方无法用一套逻辑处理。
- tag 筛选与 `meta list` 的文件名单不在本次范围，另开 Issue 并拆成两条：`meta list` 的 AND 筛选（0027:83）与 `search` 的 `tag:` 操作符（0027:97）。
