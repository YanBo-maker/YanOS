# 0001：项目准则与 Git 初始化

## INTENTION

当前目录为空，尚无持久化的开发约定或 Git 历史。项目所有者希望由 Agent 实现并逐步讲解，使用 GitHub 和细粒度提交学习开发过程。

在写第一段 CPU 代码之前，需要明确技术方向、审查方式与提交要求，以免代码推进超出理解和审查范围。本次不实现 CPU，不安装 C 工具链，不决定未来文件系统格式。

## SPEC

- 在当前目录建立默认分支为 `main` 的 Git 仓库。
- 项目文档准确反映 C17、本机运行优先与学习驱动的约定。
- 开发流程保留 INTENTION → SPEC → IMPLE → VERIFY。
- Git 采用短期任务分支和 PR，提交按逻辑能力划分，默认保留教学历史。
- 配置文本换行和生成文件忽略规则，提供简短 PR 模板。
- 初始化拆成仓库配置、项目与协作准则、PR 审查模板三项可解释的提交。
- 验证差异、文档引用、忽略规则、提交内容和远端状态。没有代码时不报告构建或测试通过。

## IMPLE PLAN

- 添加 `.gitignore` 和 `.gitattributes`。
- 添加 `README.md`、本规格和 `docs/STATUS.md`。
- 添加 `CONTRIBUTING.md`、`AGENTS.md` 和 `.github/pull_request_template.md`。
- 按三个逻辑单元提交并检查。

## VERIFY

实际检查结果、提交哈希和远端结果在本次交付中报告。此规格本身不代表验证已经通过。
