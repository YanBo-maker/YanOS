# 0020：持久化块镜像

> 状态：**Spec Lock**（2026-10-03 项目所有者批准成功前刷新、失败后停用、失败写不承诺回滚的契约）。实现与本轮验证状态见 [STATUS](../STATUS.md)。

## INTENTION

[0018](0018-block-protocol.md) 定义块请求与响应，[0019](0019-cooperative-runtime.md) 让 Guest 等待完成事件。本阶段为同一协议接入 Host 文件后端，使 Guest 写入的数据能在正常退出后由新进程读回，并明确一次失败响应能说明什么。YanFS 尚未实现；本规格不定义文件系统格式。

## SPEC

### 挂载与边界

`yan_run --disk-image FILE` 以 `r+b` 打开已有、非空的普通文件；不创建、不截断。文件大小必须是 4096 字节的倍数，且可由 Host C 的 `long` 表示；容量是文件字节数除以 4096。`--disk BLOCKS` 仍提供内存后端，两种选项互斥。

镜像采用单写者约束：挂载期间所有者不得通过另一进程修改或截断文件，后端不提供文件锁。Guest ELF、trace 与 signature 的已有文件不得与镜像指向同一文件（包含硬链接与符号链接别名）。Host 打开失败、非法镜像与关闭失败均走 Host 错误路径，退出码为 5；CLI 参数错误沿用退出码 2。

Host 回调在模拟器执行线程内同步完成。Guest 协作式等待并不让 Host 文件 I/O 异步化，Host 回调期间模拟器不会继续执行 Guest 指令。

当前 Guest 执行工具采用 POSIX/Linux 路径：文件后端使用 `fstat` / `fileno`，已有终端适配使用 `poll` / `unistd`。核心保持 C17；本轮以 WSL GCC 验证工具，不据此承诺 MSVC 工具目标可用。

### 成功与失败

块号 `lba` 对应字节偏移 `lba × 4096`。后端先校验范围，再定位文件；读必须完整取得请求字节数。写必须完整 `fwrite` 并且 `fflush` 返回成功，协议层才发布成功响应。成功响应沿用 0018：`status = 0`，`count` 为本次请求块数。

定位、短读、短写或刷新失败后，后端 `failed` 从 false 变为 true。此次请求返回 `status = 2`、`count = 0`，只发布响应头；后续合法读写同样返回设备故障，不再进行文件 I/O。容量查询仍按挂载时记录的容量回应，协议参数校验仍先于后端调用。

0018 的“失败全有全无”限定响应：错误响应不声明部分完成，也不携带部分读数据。文件内容不具备回滚保证。短写或刷新失败可能已改变部分镜像字节，`count = 0` 表示没有确认完成的块，不能据此认定介质原样不变。

关闭并重新打开可清除后端失败状态，但不会检查、恢复或修复镜像内容。调用方须自行判断不确定写入后的内容。`fflush` 提供正常运行下的跨进程可见性；本阶段不调用 `fsync`，不承诺断电持久性或原子替换块。

### 背压与关闭

Host 在调用后端前确认整帧成功响应所需的空间。空间不足时不消费请求、不执行文件 I/O，等待 Guest 释放响应环后重试。写请求重试不能重复已经执行的文件写入。

例如向块 2 写 4096 字节，偏移为 8192：空间不足时镜像与请求尾指针保持原样；完整写入并刷新后发布 `status = 0, count = 1`；短写或刷新失败则停用后端，发布 `status = 2, count = 0`。最后一种情况的镜像内容可能已改变。

退出时检查镜像的 `fclose`。失败将执行器最终结果改为 Host 错误 5，即使 Guest 先前已经报通过。关闭后清空 Host 后端对象，关闭错误不修复介质内容，也不追溯改写已经发布的响应。

## IMPLE PLAN

1. 保持 CPU / Bus / Device 与 Host / Guest 分层；文件对象、定位、读写和刷新放在 `tools/host_disk.c`，经 `YanHostBlockBackend` 接入协议泵。
2. 核对 `tools/host_block.c` 的响应空间检查先于后端操作，以及失败响应只发布头的路径；CLI 挂载与关闭放在 `tools/yan_run.c`。
3. 在 `tests/test_host_disk.c` 补强两条用例：失败后读写均拒绝且不执行文件 I/O；短写关闭重开后清除失败状态、保留部分内容，随后完整写可成功。通过测试侧 `fread` 包装计数，不改变生产接口；扩展现有变异门禁以检出绕过失败状态及重开保留失败状态。Guest 测试通过两个执行器进程验证镜像与协作式等待。
4. 在 Linux 测试配置中编译测试专用执行器，用 GNU `fclose` 包装在真实关闭后注入失败；Guest 正常读回后，确认 CLI 最终退出 5、打印关闭失败诊断且不改变镜像。该注入只适用于指定测试工件，不进入生产执行器。
5. 为 Host 变异表声明各缺陷对应的测试断言，加入无关断言失败负控；运行本轮 Release 默认套件、Debug ASan/UBSan 默认套件、全部注册变异组与门禁负控，由总审核独立核对证据和文档后按逻辑提交。

## VERIFY

- 完整写入且刷新成功后，在关闭前由独立文件句柄读回；正常退出后由新进程逐字节读回，邻块保持原样。
- 注入短写、刷新失败、短读与关闭失败，确认错误响应、后端停用和 Host 错误边界；关闭失败由测试专用执行器验证 CLI 最终退出码 5。
- 响应背压时文件回调次数为零；释放空间后请求只处理一次。
- 非法容量、镜像大小、别名输出与互斥选项显式失败；默认无磁盘执行路径保持 golden 基准。
- 变异门禁只用声明的断言或 Host 字节比对证据检出；Host 变异必须命中表中指定的测试断言。无关断言、无行为变化、挂起、崩溃与构建失败负控不得误判。

本规格不要求失败后镜像原样不变，也不以断电实验作为当前保证的验证。
