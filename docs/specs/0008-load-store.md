# 0008：Load / Store

单步中的 Guest 错误处理已由 [0009：M-mode 同步异常](0009-guest-traps.md) 更新；本文件保留对应阶段的指令规格。

## INTENTION

实现 CPU 与 RAM 之间的数据传送，在整数计算和控制转移基础上支持变量、数组与栈的内存访问。新增五条加载与三条存储指令，累计支持 37 条 RV32I 指令。

## SPEC

### 编码与地址

Load 的 opcode 为 `0x03`，funct3 的 0、1、2、4、5 分别表示 LB、LH、LW、LBU、LHU。Store 的 opcode 为 `0x23`，funct3 的 0、1、2 分别表示 SB、SH、SW。其他 funct3 返回 `YAN_UNSUPPORTED_INSTRUCTION`，不进行数据访问。

有效地址为原 rs1 加符号扩展的 12 位立即数，按 32 位回绕。Load 使用 I 型立即数（指令位 31:20）；Store 使用 S 型立即数（高七位来自 31:25，低五位来自 11:7）。Store 的 11:7 不表示 rd。

### 数据传送

CPU 经 Bus 发出数据读写，不直接操作 RAM 指针。LB / LH 将 8 / 16 位读取结果符号扩展，LBU / LHU 零扩展，LW 保存完整 32 位值。加载到 x0 仍执行访问与错误检查，成功后丢弃读取值。rd 与 rs1 重合时，地址使用写回前的源值。

SB / SH / SW 将 rs2 的低 8 / 16 / 32 位按小端写入内存，仅改变目标字节，不修改通用寄存器。rs1 与 rs2 重合时，同一个原寄存器值同时用于地址和数据；rs2 为 x0 时写入零。

`yan_cpu_step` 的 Bus 参数改为 `YanBus *`，表达执行可能写入内存。只读取指接口保持不变。成功完成访存后 PC 增加 4，按 32 位回绕。

### 失败行为

先取指，再检查编码，再访问数据。半字与字分别要求二字节和四字节对齐；字节访问允许任意地址。参数、状态、对齐、映射和完整访问范围检查沿用 Bus / RAM，失败保留 PC、通用寄存器及整个 RAM。

有效地址的计算可以回绕，单次数据传送必须完整落在映射区域内。错误继续作为 Host 状态返回，Guest 异常尚未实现。当前只有 RAM 映射，设备副作用与权限规则留在设备阶段定义。

存储可以覆盖当前指令所在内存；本次执行使用已经取出的机器码。后续取指读取更新后的 RAM。当前模型没有指令缓存，每次取指都重新读 RAM，因此 FENCE.I 不需要额外动作，其行为在 [Guest 异常规格](0009-guest-traps.md) 中定义为推进 PC。

### 规范依据

依据 [RISC-V ISA 20260120 / RV32I 2.1](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html) 的 Load and Store Instructions。严格对齐属于 Yan 平台约定；本阶段不实现 FENCE、ECALL、EBREAK 或特权机制。
