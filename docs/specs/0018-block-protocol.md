# 0018：块请求协议

> 状态：**Spec Lock**（2026-09-20 项目所有者审核通过）。实现中如需变更接口、数据结构或行为，走 INTENTION / SPEC / IMPLE 审核，不得直接修改本文件。

## INTENTION

[0014](0014-host-transport-channel.md) 的传输通道是一个**字节环，不解释载荷**。当初选它而不是给块设备另开一套 MMIO，理由正是"同一条通路要供三个消费者使用"（控制台、块设备、知识服务 RPC）。块请求协议是这条通路上定义的第一个载荷：没有它，块层只能长在设备 MMIO 上，两个消费者就得分家。

协议本身不认识文件系统：它搬运的是定长块，`lba` 是块号而不是字节偏移。块大小与将来 YanFS 的块 1:1，避免在块层与文件系统之间再插一次重打包。

## SPEC

### 传输层假设

本协议跑在 [0014](0014-host-transport-channel.md) 的两个环上：请求走 Guest → Host 环，响应走 Host → Guest 环。协议层**不新增设备寄存器**，只使用通道已有的 `G2H_HEAD` / `G2H_TAIL` / `H2G_HEAD` / `H2G_TAIL` / `DOORBELL` / `IRQ_STATUS` / `IRQ_ENABLE` / `STATUS`。

完成通知沿用 0014 的中断线：Host 写完**完整响应**并推进 `H2G_HEAD` 后置 `IRQ_STATUS.H2G_DATA`，该线经平台映射到 PLIC source 1，由 PLIC 决定是否产生 `mip.MEIP`（[0016](0016-plic-gateway-and-irq-lines.md)）。

### 定长与字节序

| 项 | 值 |
| --- | --- |
| 块大小 | 4096 字节 |
| `lba` | 以块为单位的序号，从 0 起 |
| 容量 | 以块数计（`u64`） |
| 字节序 | 小端（与机器一致；所有多字节字段都是小端） |

### 请求头（16 字节）

| 偏移 | 宽度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | `op` | 操作码，见下 |
| 1 | 1 | `flags` | **必须为 0**；非 0 即 `status = 1` |
| 2 | 2 | `tag` | 请求标识，响应原样回显 |
| 4 | 4 | `lba` | 起始块号 |
| 8 | 4 | `count` | 块数 |
| 12 | 4 | `reserved` | **必须为 0**；非 0 即 `status = 1` |

### 响应头（16 字节）

字段位置与宽度同请求头：`op` 回显、`status`、`tag` 回显、`lba` 回显、`count` 为**实际完成的块数**、`reserved` 恒为 0。

### 操作码与帧长

| `op` | 名称 | 请求帧 | 响应帧 |
| --- | --- | --- | --- |
| 1 | 读 | 16 字节头 | 16 字节头 + `count × 4096` 字节数据 |
| 2 | 写 | 16 字节头 + `count × 4096` 字节数据 | 16 字节头 |
| 3 | 容量查询 | 16 字节头（`lba = 0`、`count = 0`） | 16 字节头 + 8 字节总块数（`u64`） |

其它 `op` 一律 `status = 3`，响应只有头。

### status

| 值 | 含义 | 触发情形（非穷举） |
| --- | --- | --- |
| 0 | 成功 | |
| 1 | 参数非法 | `lba + count` 越过容量、`count == 0`、`flags != 0`、`reserved != 0`、`op = 3` 时 `lba` 或 `count` 非 0 |
| 2 | 设备故障 | Host 侧后端读写失败 |
| 3 | 不支持 | 未定义的 `op` |

**错误必须显式返回，不得静默返回零填充。** 读失败时返回全零数据会让调用方以为块内容是零，那比返回错误危险得多。

**v1 的失败是全有全无**：`status != 0` 时响应只有头、`count = 0`、且不附带任何数据；调用方要么重试整帧，要么上报。部分完成（short read / write）留给真实设备出现时再定义——把它提前写进协议，会让"完成了几块"成为每个调用方都必须处理的第二种成功路径。

### 整帧原子性与部分到达

通道是字节流：Host 可以分任意多次推进 `H2G_HEAD`，Guest 也可能在一次轮询里只看到半帧。协议层必须容忍，规则如下：

1. **先凑齐 16 字节头再解析**。不足 16 字节时一个字都不解释，包括 `op`。
2. 读第 `i` 个头字节时按下标取模：`(H2G_TAIL + i) % RING_SIZE`，因此**头可以跨环回绕**。消费侧的读位置是**消费者的读指针**（响应侧即 `H2G_TAIL`）；`H2G_HEAD` 是 Host 的生产位置，按它取模会读到载荷或尚未发布的字节。
3. 头解析成功后，按 `count` 计算期望的剩余字节数：读响应要 `count × 4096`，容量查询要 8，写响应要 0。
4. **剩余字节没有全部到达之前，不消费、不释放这一段**，也不把半个请求交给上层。
5. 校验失败的帧（`flags` / `reserved` 非 0、`op` 未知）**仍然要按帧长消费掉**，否则环里的字节流会错位；错位的表现是后续所有响应都读成垃圾，比一次显式错误难查得多。

这是本协议最容易写错的地方，VERIFY 对它有专门要求。

### 发送前流控

Guest 侧发送请求前必须按 0014 的流控契约确认空间：**整帧**（写请求是 `16 + count × 4096`）在 Guest → Host 环里放得下才写，放不下就让出重试。

- **不允许把半个头写进环**：写了一半就必须等，等于把"帧边界"这个不变量交给运气。
- 单个环的可用容量是 `RING_SIZE - 1`（0014 的"留一格"），因此 `16 + count × 4096 > RING_SIZE - 1` 的请求在 v1 无法发送：这一条要么由上层限制 `count` 上界，要么显式失败，不能靠"多试几次"绕过。
- 由此得到 v1 的环大小下界：要发得动**一个块**，需要 `RING_SIZE ≥ 16 + 4096 + 1`，按 0014 的"2 的幂"要求即 **`RING_SIZE ≥ 8192`**；`RING_SIZE = 4096` 连一个块都装不下。这条属于平台配置的验收项，不是调用方可以规避的边界。
- **读受同一条上界约束**：读的响应帧是 `16 + count × 4096`，所以 `RING_SIZE = 8192` 时**读与写的 `count` 上界都是 1**。实现取显式失败而不是截断：Guest 层用 `max_count` 拒绝并**一个字节都不写**，Host 对"响应放不下"的读回 `status = 1`。
- "空间不足"是 **Guest 侧可以检测并处理的条件**，不是设备错误；不要把它翻译成协议 `status`。

### 顺序与 tag

单 hart、单队列，因此按到达顺序处理，**响应顺序 = 请求顺序**。调用方可以据此把请求与响应按顺序配对，不必依赖 `tag`。

`tag` 为将来的并发/乱序保留：v1 允许恒为 0，且**响应必须原样回显**请求里的 `tag`——回显是实现里唯一需要为将来保留的行为。

### Guest 侧平台视图

协议需要的通道寄存器在当前 `os/platform.h` 里**尚不存在**（该头目前只重述 UART 与 PLIC 源号）。实现前需要按 0017 的分区补上通道常量与访问器，并把它们纳入 `tests/test_boot.c` 的防漂移比对（0017 的 A1 / A2 已经为该文件建立了做法）。这是本规格落地的前置改动，不是实现细节。

### 明确不在范围内

不做多队列；不做乱序与并发请求；不做 DMA 与描述符链；不做 discard / TRIM；不做分区表；不做缓存（缓存属于 Guest 侧，且不在本阶段）；不做部分完成语义；不做加密或校验和；不定义文件、目录或任何上层结构。

## VERIFY

- **帧边界**：头分两次到达（1 + 15、8 + 8）；数据分多次到达；**头跨回绕**与**数据跨回绕**各一例；一次到达整帧。
- **校验**：`flags != 0`、`reserved != 0`、未知 `op` 都必须 `status != 0` **且按帧长正确消费**，后续帧不错位。
- **错误显式**：读失败返回 `status != 0`，**不返回零填充数据**；`count == 0`、`lba + count` 越界各一例。
- **容量查询**：`op = 3` 的 8 字节结果正确；`lba` / `count` 非 0 时为参数错误。
- **流控**：空间不足时**一个字节都不写**，让出后重试成功；`RING_SIZE - 1` 边界上的最大可发帧。
- **顺序与 tag**：连续多个请求的响应顺序与请求一致；`tag` 原样回显。
- **完成通知**：Host 只在写完完整响应后置 `IRQ_STATUS.H2G_DATA`；半帧期间不置位；清除后该源撤销（0016 的电平语义）。
- **变异检查**：至少注入 5 个缺陷（凑帧时提前解析、消费时不按帧长、校验失败不消费、`count` 乘块大小时不回绕检查、半帧就置中断），确认测试逐一报错、无存活者。
- 命令：Debug ASan/UBSan 与 Release 下的 `cmake --build` 与 `ctest --output-on-failure`。
