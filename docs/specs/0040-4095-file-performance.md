# 0040：4095 文件性能验收与局部优化

- **意图**：在4095篇笔记的满库夹具上，让常用终端操作达到统一指令步数门槛，并提供可重跑的正确性、计步和任务栈证据。依据：[0004 决策](../decisions/0004-4095-performance-budget.md)。
- **状态**：Implemented；所有者于2026-10-27认可意图与成功标准并授权合入，[PR #93](https://github.com/YanBo-maker/YanOS/pull/93)以merge commit `552dcde`进入main，保留阶段历史。验收范围见VERIFY。
- **supersedes**：承接0036-R5-AC1引用的4095性能验收；不取代0036的1023/2047要求、历史结果或其余文件系统契约；澄清0032解析器仅blocks[0..block_count)为有效结果。
- **成功标准**：4095档九项均达到门槛；三档同时复测，输出、统计、分配位置、错误与镜像符合现行规格；任务栈与整体内存保持预算；实际验收入口及检测力可由其他检出重跑。

## 当前问题

0036支持4095容量，既有性能测试实际只测1023/2047。外部0040旧文件没有进入仓库，本草案根据已批准条款、所有者新裁定与当前源码重新制定方案，不把旧文件视作已恢复的依据。

## 0040-R1：保持分配规则，降低新建成本

现有分配器枚举候选位置并反复遍历目录。实现在已持有busy的同步区内，临时复用名称下标表收集非空extent，按起点排序，线性寻找最低可用连续区间；所有成功/NOSPACE返回前均恢复完整名称表，之后才允许I/O。零长度文件仍进入恢复后的名称表。不得借用覆盖操作的旧extent，不增加随N增长的栈数组。

- R1-AC1：create、replace、copy在碎片和不同slot顺序下，选择的起点与独立最低空隙oracle相同；空文件、精确相接、最前空隙和NOSPACE均覆盖。
- R1-AC2：成功、NOSPACE、数据写失败及目录写失败之后，名称表与缓存目录对应；既有INVALID/BUSY/FAULTED优先级和零I/O拒绝规则保持。

## 0040-R2：减少内存和名称处理的重复工作

实现展开现有Guest内存助手的对齐字批次，保留不对齐头尾、零长度和返回指针语义；反向重叠复制必须从高地址向低地址。名称比较一次遇差异或NUL便结束，保持ASCII前缀顺序。名称保护检查可用纯算术证明整个候选跨度安全；不能证明时回退原逐字节检查，不因短名后方的保护区而新增拒绝。

- R2-AC1：字节oracle覆盖正反重叠、独立对象、对齐、批次边界及守卫；名称oracle覆盖前缀、31字节、末尾NUL和排序输入。
- R2-AC2：名称NUL紧邻context、目录和名称表的合法边界仍成功；真实重叠、指针域溢出及原非法输入仍按原顺序拒绝。

## 0040-R3：消除同次查询中的无用读取和搬运

完整文本资格检查必须先于引用或索引发布。对确定的ASCII状态使用等价快路，保留UTF-8跨段和CRLF状态；搜索的非零ASCII资格规则与块文本控制字符规则分别实现。小文件只有在完整预检成功、且实际完整内容仍在现有缓冲中时，才能复用该缓冲分词；大文件仍流式读取，不引入跨文件或跨查询缓存。

块服务只需要正文起点。实现提取现有元数据解析的单一核心：原公开入口保持完整结果复制及失败输出不变，内部受限入口只返回经过同样语法校验的正文起点。不得复制出另一套头语法。块解析器只重置控制状态，并在新槽发布前完整初始化该槽；所有者2026-10-25批准：仅blocks[0..block_count)为有效结果，未使用槽不承诺清零；每个新槽在启用前仍完整初始化。首次init前的整对象零初始化责任、INVALID/BUSY全对象保持、STOPPED重置及有效块空行号规则保持。

协议头只读peek在已有available检查后使用一次size/base/tail快照；tail须按ring大小归一化，保留回绕，不移动tail，不消费部分帧。两个调用模块共享内部helper；编码、长度、配对、fence和整帧消费规则不变。

- R3-AC1：中文、跨段UTF-8、CRLF、末尾NUL/非法字节、4095/4096/4097字节边界及相邻文件污染均保持原结果；资格失败不发布部分索引或引用。
- R3-AC2：旧元数据接口成功结果及全部失败输出保持；内部正文起点与原解析结果相同。块解析器重复init、短ID覆盖长ID、空范围、重复ID、64/65块、BUSY/STOPPED和失败保持均覆盖。
- R3-AC3：peek的完整/不足头、跨ring边界、归一化位置及状态变化控制保持原帧判据；不得用当前夹具中的规范化tail替代通用回绕验证。

## 0040-R4：独立验收与原始证据

新增独立执行器/判定器，复用现有生产Guest与Host驱动；默认CTest中注册实际Guest验收，纯判定器控制也可在Windows运行。只使用本任务独占工作目录，不清理或覆盖已有目录；工作目录参数作为容器，每次创建唯一子目录保存该次证据，重复验收不覆盖旧结果。缺仓库源码/产物是失败，缺外部依赖为NOT VERIFIED，不当作通过。

- R4-AC1：独立核对完整目录、CRC、名称、正文、extent和尾零；完整输出的行、排序、total/shown、物理位置、回执及退出状态正确。只看成功回执或镜像哈希不足以通过。
- R4-AC2：错行/漏行、错误总数/顺序、缺失或乱序计时、零/超限步数、错误退出、截断输出和镜像变化均被特定断言拒绝；timeout、信号、sanitizer和构建错误不冒充行为检出。
- R4-AC3：保存源码/工具/产物/夹具身份、命令、stdout/stderr、状态、原始输出及完整矩阵；未完成时保留已完成范围，不伪造整组通过。

## 0040-R5：最终性能与内存门槛

- R5-AC1：N=1023、2047、4095分别装满。九项为启动至首提示符（沿用旧mount指标）、create、ls、backlinks、related、block backlinks、meta list、meta list tag:t、search x。每项均不超过50,000,000 Guest步。每项独立启动，search包含首次索引构建。
- 计步从UART消费命令末尾LF到完整新提示符的末字节；启动指标从启动到首提示符。create先删除slot floor(N/2)，再创建同名同大小内容，删除不计入create区间；最终全镜像恢复原样。
- 比较夹具保持原性能配方：f0000.txt至f(N-1).txt按slot升序；中间槽为60个a，其余是65字节笔记，含tag:t、指向f0000.txt的整文件链接、块x及对应正文引用。完整配方在后续独立测试模块中受跟踪；另以名称乱序夹具验证排序，不能混改历史比较基准。
- R5-AC2：每项任务0栈观察值不超过4KiB，并核对分配/挂载校验的静态栈帧不随N增长。动态值只代表本次在范围内的采样，不证明所有路径无越栈。实际arena须与当前十一项align16公式相同；Guest加载段及最大arena保持32MiB预算，三处64KiB context断言保持。
- R5-AC3：修补现有arena预算脚本漏计R8四张下标表的问题，并用能区分旧/新总量的预算边界控制验证其检测力。

## 非目标与实施顺序

不改磁盘格式、Host/Guest协议、MCP schema、命令输出、来源身份、固定索引容量或失败不回滚规则。目标是固定验收夹具的可重复门槛，不是任意长正文的恒定耗时承诺。

顺序为：方案核对→独立门禁与反例→逐组局部优化与实际RV32复测→三档完整验收→三平台默认回归与实际变异→独立代码/文档审核及总审。内部入口、名称表临时复用和有效块范围按本方案实施；后续未规定的语义缺口仍须先对齐，不能由原型结果默认为已批准。
