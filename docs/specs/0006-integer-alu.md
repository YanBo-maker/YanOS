# 0006：RV32I 整数计算

## INTENTION

在 ADDI 单步执行基础上补齐整数计算，为后续分支条件、地址计算和访存提供运算能力。本阶段共支持 21 条整数计算指令。

## SPEC

### 指令范围

| 格式 | 指令 |
| --- | --- |
| 寄存器与立即数 | ADDI、SLTI、SLTIU、XORI、ORI、ANDI、SLLI、SRLI、SRAI |
| 寄存器与寄存器 | ADD、SUB、SLT、SLTU、XOR、OR、AND、SLL、SRL、SRA |
| 高位立即数 | LUI、AUIPC |

沿用 `yan_cpu_step` 接口：成功写回 rd 并将 PC 增加 4，失败保留状态。运算不修改 RAM；x0 丢弃写入。读取全部源值后再写回，允许目标与任意源寄存器重合。取指和错误处理沿用 0005。

### 编码与运算

OP-IMM 的 opcode 为 `0x13`，OP 为 `0x33`。两者的 funct3 对应加减（0）、左移（1）、有符号比较（2）、无符号比较（3）、异或（4）、右移（5）、或（6）、与（7）。

非移位立即数采用 12 位符号扩展，包括 SLTIU。立即数移位使用位 24:20；SLLI、SRLI 的位 31:25 必须为零，SRAI 必须为 `0x20`。寄存器运算的 funct7 通常为零，仅 SUB、SRA 使用 `0x20`。其他组合返回 `YAN_UNSUPPORTED_INSTRUCTION`，即使 rd 为 x0 也检查编码。M 扩展仍未实现。

加减保留低 32 位。比较结果为 0 或 1；逻辑运算逐位执行。寄存器移位仅取 rs2 的低 5 位，移位范围为 0～31。逻辑右移高位补零，算术右移补源值的符号位。

LUI 的 opcode 为 `0x37`，把指令位 31:12 放入 rd 的高 20 位，低 12 位清零。AUIPC 的 opcode 为 `0x17`，将相同立即数加到当前指令的 PC，结果按 32 位回绕。这两条指令没有 rs1 或 funct3 字段；对应位属于立即数。

### C 语义

运算使用无符号定宽值。有符号比较通过翻转符号位后比较大小实现。算术右移显式补高位，并单独处理移位量零，避免负数右移和移位 32 位。解码先验证受限字段，随后计算结果，最后统一写回。

### 规范依据

依据 [RISC-V ISA 20260120 / RV32I 2.1](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html) 的 Integer Computational Instructions。当前范围不包含控制转移、访存、FENCE、系统指令和扩展指令，尚不声明完整 RV32I 支持。
