# 0004：CPU 状态与取指

## INTENTION

阶段 0 已能通过 Bus 访问 RAM。下一步让 CPU 保存执行位置和寄存器，并使用 PC 发起取指，为指令解码与执行建立入口。

本阶段覆盖 CPU 状态、寄存器访问、复位、取指及 Machine 集成。解码、执行、CSR、异常处理和中断留待后续任务。

## SPEC

### 状态与寄存器

`YanCpu` 保存 32 个 32 位通用寄存器及 `pc`，使用前零初始化。CPU 自身不分配内存，也不保存设备地址或 RAM 指针。

寄存器通过 `yan_cpu_read_reg`、`yan_cpu_write_reg` 访问，编号范围为 0～31。读取 x0 得到零，写入 x0 成功但丢弃写入值；其他寄存器完整保存 32 位数据。非法编号返回 `YAN_OUT_OF_BOUNDS`，空参数返回 `YAN_INVALID_ARGUMENT`。错误保留原寄存器和读取输出。

结构体字段供状态观察使用，寄存器修改经过接口。测试可以直接设置 PC，以覆盖尚无跳转指令时的不同取指地址。

### CPU 复位

`yan_cpu_reset(cpu, entry)` 检查入口按 4 字节对齐，然后清零寄存器并设置 PC。入口未对齐返回 `YAN_UNALIGNED`，CPU 状态保持原值。

入口是否映射由取指时的 Bus 检查。CPU 复位独立于内存，因此允许对齐但未映射的入口。寄存器统一清零及默认入口 `0x80000000` 是 Yan 平台约定。

### Bus 取指

Bus 增加 `YAN_ACCESS_FETCH` 和 `yan_bus_fetch32(bus, address, instruction)`。返回沿用 `YanBusResult`，宽度固定为 4，种类始终为 FETCH，包括错误结果。

当前唯一映射为可取指的 RAM，数据读取与取指共用地址验证和小端读取路径。检查参数、对象状态、地址对齐、起始地址与完整访问范围。失败保留输出值。

设备实现时再定义各区域的取指权限；当前不增加设备注册或权限框架。

### CPU 取指

`yan_cpu_fetch(cpu, bus, instruction)` 使用当前 PC 调用 Bus 取指。成功返回原始 32 位机器码，保留 PC、所有寄存器和 RAM。连续取指可得到同一字；任意位模式均可读取，编码合法性由后续解码器判断。

未对齐、未映射和跨越 RAM 末尾分别沿用 Bus 错误。返回值保存出错 PC、宽度 4 和 FETCH 种类。CPU 指针为空时返回参数错误，地址字段为零，输出保持不变。

本阶段的错误是 Host 可检查的状态值。Guest 异常入口及跳转指令对目标对齐的处理属于后续规格。暂不提供 `step()`，以免把取指误计为指令完成。

### Machine 集成

- Machine 新增 CPU 状态。初始化成功后 PC 为 `0x80000000`，寄存器与 RAM 均为零。
- `yan_machine_reset` 保留 RAM 缓冲区与映射，清零 RAM，并把 CPU 恢复到默认入口。
- 单独调用 `yan_cpu_reset` 保留内存和 Bus 映射。
- 镜像装载只改变镜像覆盖的 RAM 区域，保留 CPU 状态。
- Machine 释放后解除映射、释放 RAM，并清零 CPU 状态；继续支持释放后重新初始化。

### 示例与验收

装入字节 `93 02 70 00` 后，从 `pc = 0x80000000` 取指，得到 `0x00700293`。取指完成后 PC 保持原值，x5 仍为零。

测试覆盖全部寄存器编号、x0 写入丢弃、32 位数据、无效参数和复位失败后的状态保持。取指测试覆盖重复读取、零字、RAM 首尾、32 位地址顶部、未对齐 PC、未映射 PC、跨界访问和错误输出保持。

集成测试区分 CPU 复位与整机复位，检查镜像装载及多个 Machine 的状态独立性。阶段 0 的测试和内存示例继续运行。

### 规范依据

采用 [RISC-V ISA 20260120 中的 RV32I 2.1](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html)，参照 Programmers' Model 和 Base Instruction Formats 两节：32 位通用寄存器、x0 固定零、PC 与 4 字节指令对齐。

本阶段只实现状态与读取行为，尚不声明 RV32I 指令支持。
