# 0002：YanCPU 设计方案

状态：提案，待审查。当前仍处于 Phase 0，尚无 CPU 实现。文中的新增接口和平台参数均为建议值。

## INTENTION

为第一版 YanOS 提供可理解、可调试的 RISC-V 执行环境。它需要运行 C 编译的程序、访问内存和设备，并能把异常与中断交给 Guest 处理程序。

学习目标是沿着一段程序解释寄存器、内存和执行位置的变化。通过逐步实现这些行为，建立后续启动代码、驱动和文件系统的实验基础。

在编码前确定 CPU 状态、平台边界和验收程序，可以避免各模块对启动、访问错误及单步行为作出不同假设。首轮设计覆盖功能行为；电路时序、流水线、缓存性能、MMU、多核和应用隔离留待后续需求。

## SPEC

### 1. 目标配置

| 项目 | 提案 |
| --- | --- |
| 实现 | C17 功能模拟器，本机命令行运行 |
| 指令集 | 最终达到 RV32IM_Zicsr |
| 寄存器与地址 | 32 位 |
| 字节序 | 小端 |
| 执行核心 | 单核，单 hart，即一个独立执行上下文 |
| 特权 | 仅 M-mode，第一版 Guest 全部运行在机器模式 |
| 指令长度 | 32 位，指令地址按 4 字节对齐 |
| 外部访问 | CPU → Bus → RAM / Device |

RV32I 提供基础整数指令；M 扩展增加整数乘除法；Zicsr 提供访问控制与状态寄存器的指令。异常和中断还依赖机器模式的特权架构，单独实现 Zicsr 并不能完成这部分系统行为。

M-mode 初版运行可信 Guest。它可以承载启动、驱动和简单系统服务，应用与内核之间的权限隔离需另行设计。

分阶段记录实际支持的指令。开发中的子集采用明确的能力清单，完成相关行为和验证后才标记 RV32IM_Zicsr 支持。

### 2. 模块职责

| 模块 | 保存或处理的内容 |
| --- | --- |
| CPU | 通用寄存器、PC、已实现的 CSR、指令执行及陷入处理 |
| Bus | 地址映射、访问宽度、区域边界与错误返回 |
| RAM | Guest 的字节数据 |
| Device | 设备寄存器、输入输出状态及中断信号 |
| Machine | 组装 CPU 与平台，组织冷启动和设备推进 |
| Runner | 加载程序、控制运行次数、显示调试结果 |

PC 是当前指令地址。CSR 是控制与状态寄存器，用于表达系统控制状态。陷入（trap）是异常或中断引发的控制转移。

终端地址映射由 Bus 管理，Host 文件操作由加载器和设备适配处理。Guest 的读写请求经 Bus 到达设备。RAM 使用字节寻址；任何 Guest 地址都要经过映射检查。

### 3. 状态与启动

初始 CPU 状态包含 `x0～x31` 和 `pc`。`x0` 始终为零。后续加入 CSR 时分别定义读写掩码、固定字段、复位值和错误行为。

建议采用原项目设想中的平台参数：

| 参数 | 建议值 |
| --- | --- |
| RAM 起点 | `0x80000000` |
| RAM 容量 | 32 MiB |
| RAM 末地址 | `0x81FFFFFF` |
| 启动 PC | `0x80000000` |
| 程序初始格式 | 平坦二进制镜像 |

冷启动由 Machine 清零 RAM、装入程序，再复位 CPU。镜像第一个字节放在 RAM 起点；超过 RAM 容量的镜像在复制前拒绝，并报告错误。

CPU 复位将通用寄存器清零、设置启动 PC，并恢复已实现 CSR 的复位状态。该操作保留 RAM 内容，便于重新执行已加载的程序。通用寄存器统一清零是本平台的确定性约定。

栈指针由 Guest 启动代码设置。CPU 执行期间不自动创建栈、清零 C 全局变量或调用 `main`；这些行为属于启动代码。

### 4. 执行与调试接口

下表定义行为，具体 C 函数签名在模块规格中确定。

| 操作 | 行为 |
| --- | --- |
| `cpu_reset(entry)` | 恢复 CPU 状态，将 PC 设置为有效且对齐的入口 |
| `cpu_step()` | 检查可接收中断；若未进入中断处理，则尝试执行当前一条指令 |
| `machine_run(max_steps)` | 最多推进指定次数，返回停止原因和统计 |
| 读取调试状态 | 查看 PC、寄存器和 RAM，保持 Guest 状态不变 |

`cpu_step()` 区分指令完成、Guest 陷入、阶段能力缺失和 Host 执行错误。返回执行前后的 PC，并在成功取指时包含原始机器码。

一条正常指令完成时记录一次完成数；指令异常或接收中断时记录陷入结果。进入陷入处理的这一步不继续执行处理程序的第一条指令。`machine_run` 按步数设置上限，保证反复异常的程序也能交还控制权。

阶段能力缺失表示模拟器仍在开发中，例如当前测试目标使用了尚未实现的 RV32I 指令。完整目标中不支持的扩展或非法编码按 Guest 非法指令异常处理。Host 内部错误单独报告，避免被当作 Guest 行为。

第一阶段提供有界运行和只读状态显示。终端交互需要长时间运行时，再定义暂停请求的处理方式。读取设备寄存器可能产生副作用，通用调试读取初期限定于 CPU 状态和 RAM。

### 5. 内存访问与错误

Bus 支持 8、16、32 位读写，并区分取指与数据访问。一次请求必须完整落在同一映射区域，映射区域相互独立。

平台初版要求自然对齐：16 位访问地址为 2 的倍数，32 位访问地址为 4 的倍数。CPU 在产生设备副作用前检查对齐；Bus 在读写前检查整个范围。被拒绝的写入保留原内容。

RAM 允许取指，MMIO 初版只允许数据访问。未映射地址、越界请求和设备不支持的宽度返回访问错误；CPU 在异常机制完成后转换成对应 Guest 异常。早期取指模块先返回可检查的错误结果，异常阶段再接入处理入口。

错误信息至少包含访问种类、地址、宽度和原因。Guest 运算的 32 位回绕与 Bus 的范围检查分别处理，Host 指针运算不能绕过范围验证。

### 6. 异常、中断与设备

先实现同步异常，例如非法指令和访问错误，再接入定时中断。异常规格需要定义原因编码、保存位置、入口地址和返回行为。

系统处理路径涉及 `mstatus`、`mtvec`、`mepc`、`mcause`、`mtval`、`mie`、`mip` 等 CSR，以及 `MRET`。这是一组阅读入口；完整 CSR 清单、必需寄存器、字段约束和计数器行为应在特权规格中逐项核对。

建议先支持直接入口：异常与中断进入同一个处理入口，Guest 根据原因分派。CSR 配置、中断优先级和 `WFI` 行为在该阶段单独确定。

平台设备顺序为字符输出、字符输入、计时器、块设备。终端先使用轮询，计时器再引入中断。原有 MMIO 区域作为地址候选，具体寄存器布局在驱动实现前确定。

测试采用可控的平台时间与输入事件。设备时间的推进规则属于 Machine；中断阶段明确正常指令、陷入和等待状态各自怎样推进时间，保证测试可复现。

### 7. Guest 构建与加载

首个 C Guest 采用 freestanding 环境，即自行提供启动和所需运行支持，使用 ILP32 整数调用约定。编译目标只启用当前已经实现的扩展，检查生成的机器码后加载。

工具链负责生成 ELF，再转换为平坦镜像。ELF 保留符号与调试信息，初期 Runner 加载平坦镜像。链接脚本固定入口和内存布局，启动代码建立栈、初始化必要数据，再进入 C 函数。

首批程序通过内存结果和 Guest 字符输出验收。测试 Runner 按指定 PC 或步数上限停止；`ECALL`、`EBREAK` 保持架构语义。具体编译命令、运行库依赖和链接布局在 Guest 启动规格中验证。

### 8. 分阶段验收

| 阶段 | 可观察结果 | 主要学习内容 |
| --- | --- | --- |
| A：状态与取指 | 复位、装载、取出已知机器码，错误访问可诊断 | 地址、字节序、寄存器与 PC |
| B：整数执行 | 循环计算 1 至 10 的和，将 55 写入 RAM | 解码、运算、分支、访存 |
| C：最小 C Guest | 函数调用、数组操作和字符输出正确 | 编译、调用约定、栈、MMIO |
| D：乘除法 | 运算与边界用例符合 M 扩展 | 定宽整数、符号与特殊结果 |
| E：系统控制 | Guest 处理异常与定时中断并恢复执行 | CSR、处理入口、上下文保存 |
| F：CPU 基线验收 | 指令清单与系统测试完整通过 | 规范符合性与回归验证 |

各阶段继续拆成小提交，分别附对应测试。B、C 阶段仍按已支持子集运行程序；RV32I 中的系统指令行为随异常机制补齐。只有 F 阶段通过后才标记完整 CPU 基线。

YanOS 的最小启动可以在 C 阶段开始验证。块设备和持久化作为后续平台任务，通过 Guest 驱动接入。

### 9. 首个任务：状态与取指

首个任务只覆盖阶段 A。示例内存为：

```text
地址          字节
0x80000000    93 02 70 00

取指结果      0x00700293
```

这组机器码对应 `addi x5, x0, 7`。阶段 A 只读取它：取指后寄存器和 PC 保持原值。指令执行留到阶段 B，届时验收 `x5 = 7`、`pc = 0x80000004`。

首批测试覆盖复位状态、小端取指、RAM 首尾合法读取、未对齐访问、跨界读取、超长镜像拒绝和失败后状态保持。测试先于实现，配套实现和测试一起提交。

### 10. 审查重点

1. 以 RV32IM_Zicsr、M-mode 作为第一版目标，按实际能力分阶段交付。
2. 沿用 32 MiB RAM、`0x80000000` 启动地址，初期加载平坦镜像。
3. 使用严格对齐访问，单步区分指令完成与陷入，运行上限按步数计算。
4. 先验收状态与取指，再执行指令；最小 C Guest 提前参与平台验证。
